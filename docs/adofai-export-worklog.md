## 一、关键游戏机制与术语（务必记住）

- **angleData 记录的是绝对角度**（0=向右，180=向左）。但"两次点击和为 180°"这类判定，说的是**相对转角之和**。
  例：绝对序列 `180,180,30,0,0` → 相对转角 `0,0,150,30`，`150+30=180`。
- **完美判定窗口 ±30°**。一次转角越大，两个音砖间的时间越短（时间 = (180−|转角|)/180 拍）。
- **不可能有真双押**（同拍两次按下），只能做"**伪双押**"：
  两个连续点击的**相对转角之和 = 180°**（=1 拍），其中小角 `a ≤ 30°`；
  两次点击相对中心各偏移 `a`，间隔 `2a ≤ 60°`，都落在完美窗口内。
- **floor 语义**：`angleData[0]` = floor 0 = **起始砖（不按）**；我们按下的**第一拍是 floor 1**。
  动作里的 `floor` 与 `angleData` 下标对齐（0 基）。
- **Twirl（旋转）**：放在折返格上，让两次按键判成"同拍"，否则会被读成
  "双押 → 单按两次 → 双押"的交替。Twirl 会翻转其后所有转角的符号。
  - 不能"既把镜像烘进 angleData、又放 Twirl 事件"——两次镜像会互相抵消，游戏里看不到旋转。
- **"多边形"不是多押**：是 **24 分音符快速跑动**形成的折线形状；它的走向符号要跟随双押折返方向。
- **近整拍吸附**：工程里因毫秒取整会出现 `0.9668`、`1.0063` 这类拍差，直接算角度会产生几度
  的"意义不明的弯曲"。需吸附到最近的整数拍（容差 0.05 拍），但 1/2、1/3、1/4 等细分不受影响。

## 二、当前算法要点

函数 `buildAngleData(beats, counts, multiPlan, multAt, twirlSet, diffTable)`：

- 状态机：多押点改写 `state = {multiType, maxKeys, angle}`，作用于其后所有 beat；初始 `single`。
- 只处理**真·多押**（同 beat ≥2 个音砖）；普通单押不处理。
- `step = wrap360((1 − diffEff) × 180)`，其中 `diffEff = diffTable[j] × mult`（diffTable 已吸附）。
- 方向量：
  - `stepSign`：双押折返后设为折返方向 `s`，让后续 24 分跑动（多边形）朝正确一侧展开。
  - `rotSide`：记录当前多押折返方向，用于判断 3/4 押是否需要补 Twirl。
- 三种多押形态：
  - **中旋（midspin）**：原格前插 `[X₁,999,X₂,999,…]`，零净偏移（`MIDSPIN=999`、`DP_MIN_TRAVEL=15`）。
  - **多押（multi），押数=2（伪双押）**：原格后插入折返块，`second = 当前方向 + s·(180−angle)`，
    回落 `carry = s·angle`；`stepSign = s`；折返格放 Twirl（**跳过 j=0，即开头的第一拍**）。
  - **多押（multi），押数>2**：按 `当前 + (180−angle)` 插 `blocks` 块；仅当折返方向与 `rotSide`
    不一致时，在第一个插入格补一个 Twirl（避免方向已对时再翻一次导致出错）。
- 近整拍吸附：`snapDiff(raw, gridDiv)`（`NEAR_INT_TOL = 0.05`，`gridDiv` 取快照的 `gridDiv`），
  由 `buildDiffTable` 统一计算一次，供角度、`Pause`、夹角检查共用。

### 2026-11-22 · 快速跑动统一为"N 同号成组、逐组换向"（三角/之字）+ 奇偶 Twirl
- **换算确认**（用户定）：行进角 = 180 × 拍差；转角 = `(1 − diffEff) × 180`。
  行进 `4=180, 6=120, 8=90, 12=60, 16=45, 24=30, 32=22.5`；
  转角 `4=0, 6=60, 8=90, 12=120, 16=135, 24=150, 32=157.5`。
- **生成规则**（A 案，以范例为准）：
  - 8 分（拍差 1/2）→ 三角 N=2（`++--`，不再成正方形）；
  - 6 分（拍差 2/3）→ 三角 N=3（`+++---`）；
  - 16 / 32 分（拍差 1/4、1/8…，2 的幂倒数）→ 之字 N=1（`+-+-`）；
  - **12 / 24 分（拍差 1/3、1/6…）→ 同号（螺旋，不之字）**，避免主工程多边形缠成一团。
- **Twirl**：只在**组首**、且本组方向与上一组不同时补一个（**不是每组第一个都放**），
  用 `rapidSide` 记录上一组方向。与 123123 样例的 8 分（12,14 / 17,19,21,23）吻合。
- **验证**（`16分测试.bdg`）：8 分段变为 `90,180,90,0,…`（三角）；16 分段 `+135,-135,…`（之字）。
- **待办**：交界处仍有"多余 Twirl / 该转而没转"的个别点（用户截图指出），需按具体 floor 微调。

### 2026-11-22 · angleData 改为"连续不 wrap" + 发卡强制同号（修 1/2 拍交替）
- **现象**：多个连续 2 拍发卡弯，游戏里暂停/时长变成 `1, 2, 1, 2…`。
- **根因**：`angleData` 被写成 `0,180,0,180…`。游戏按**有符号转角**判定，
  `0→180 = +180`、`180→0 = −180`，符号一正一负交替，游戏就把连续回头块读成 1 拍 / 2 拍交替。
- **修复**：`buildAngleData` 返回前增加后处理：
  1. 把整条 `angleData` 转成**连续不 wrap**（按 `sdk = ((Δ % 360)+540)%360−180` 累加）；
  2. 所有发卡弯（`| |sdk| − 180 | < 0.5°`）统一取**首次出现的符号**（恒定 `+180` 或 `−180`），
     使连续发卡为 `0,−180,−360,−540…`，游戏按 2 拍播放。
  3. `999` 中旋格及其前一项跳过，中旋组保持原样（不破坏 midspin 结构）。
- **验证**（真实加载插件 renderer.js，桩 api 端到端导出）：
  - `16分测试.bdg`：连续发卡输出 `0,−180,−360,−540,−720…`，delta 恒为 `−180`；
    Pause 全部为 `2`（floor 1–8、41），不再 `1,2` 交替。
  - `111.bdg`：8 分三角为 `+90,+90,−90,−90` 循环（正确）；
    12/24 分同号螺旋（如 `300,420,540`，delta 恒 `+120`）；无 999（该工程用 multi 而非 midspin）。
- **注意**：不 wrap 会让角度值累积变大（主工程实测 `−510 ~ 2700`）。这是螺旋段正常累积，
  游戏内部按模 360 处理；**不可**中途单独归一某个值，否则会产生 ±360 的假转角（正好是本次要修的 bug）。
- **调试手法（复用）**：用桩 `window.__bdgPluginRegister` + 桩 `api.project.snapshot()`
  直接 `require` 插件 `renderer.js`，捕获 `registerExporter` 的 `run()` 与 `system.writeText` 内容，
  即可对任意 `.bdg` 做端到端导出校验，无需启动 Electron。

### 2026-11-22 · 排版"恒定向上"：闭环段镜像
- 现象：多押 + 8 分形成的"三折弯"会朝下（如 deltas `+165,+105,+90`，和 360，峰值朝向 270），
  各段还会上下交替，不好读谱。
- 做法：`buildAngleData` 在"不 wrap + 发卡同号"之后再加一个后处理：
  1. 顺序扫描，找**闭环段**：连续 `|delta| ≥ 30` 的块，累计转角达到 `|acc| ≥ 300` 且 `acc ≡ 0 (mod 360)`；
  2. 段内 `sin(朝向)` 之和 `< 0`（整体朝下）时，把该段所有 delta **取反**（沿水平轴镜像）；
  3. 幅值完全不变 ⇒ **时序不变**；段末用整体平移拉回原值，保证与后续段连续（不产生假 360° 转角）。
- 验证（`111.bdg`）：三折弯段由 `165,105,90`（峰 270）变成 `-165,-105,-90`（峰 90，朝上）；
  `16分测试.bdg` 回归：连续发卡 `-180` 恒定、8 分三角 `+90,+90,-90,-90`、Pause 全 2，均未受影响。
- **术语补充**（用户）：8 分段的相对角度应是 **90**（不是 270）；4 分段则相反；
  多押折返**必须走内圈（< 180）**——现有 `157.5 / 165` 已满足。
- 待办：用户将提供"期望的"参考文件，用于最终校准三折弯附近的 Twirl 位置。

### 2026-11-22 · 插件热重载（改完不用重启）
- 根因（两处，缺一不可）：
  1. 主进程 `plugins.ts` 没有监听插件目录，改文件后不会重新扫描；
  2. 渲染层 `host.ts` 的 `loadRenderer` 有 `if (actives.has(id) || loading.has(id)) return;`，
     而 `replaceEntries` 只销毁"已禁用"的插件 ⇒ **已启用的插件永远不会用新源码重新激活**
     （这也是原来"重新扫描并加载"按钮对代码修改无效、只能重启的原因）。
- 修复：
  1. `src/main/plugins.ts` 新增 `installPluginWatcher()`：`fs.watch(userPluginsDir(), {recursive:true})`，
     250ms 防抖后 `rescanPlugins()`；`will-quit` 时关闭。
  2. `src/renderer/src/plugins/host.ts`：`replaceEntries(list, force)`，
     `refreshPlugins()` / `reloadPlugins()` 传 `force=true` ⇒ 先 `disposeRenderer` 全部，再按新源码
     `loadRenderer` 重新激活（贡献项随 finalize 清理，不会重复注册）。
- 效果：保存 `renderer.js` 后约 0.25s 自动热重载；也可点「设置 → 插件 → 重新扫描并加载」手动触发。
- 验证：`npm run typecheck` ✓、`npm run lint` ✓、`npm run build` ✓、electron-builder ✓
  （首次打包因 `release/` 被占用失败，重跑成功）。
- 产物：`release\Beat-Data-Generator-0.3.15-setup.exe`（未提交）。

### 2026-11-22 · 装饰泳道布局重做（自动间隔 / 居中 / 播放头行程）
- 用户要求：按参考示例**横向排列**；**自动选一个"四分音符间隔"**；泳道以中线对称；
  播放头在**最中心**（偶数条时为中间两条的交界）；行程由**最后一个菱形的 x** 决定。
- 实现：
  - `spacingX`（四分音符间隔）：默认 `0 = 自动`，取 `clamp(80 / 总拍数, 0.2, 1.0)`，
    可用面板「四分音符间隔 (格，0=自动)」手动覆盖；
  - `x = (beat − 首拍) × spacingX`（不再是砖块曲线坐标）；
  - 泳道 `y = (i − (n−1)/2) × laneGap` ⇒ 4 条时 `-0.75/-0.25/+0.25/+0.75`，中心为 0；
  - 小节线 `x = k×bpb×spacingX`，以 y=0 居中纵向拉伸；
  - 播放头起点 `(0, 0)`，每拍 `positionOffset=[拍差×spacingX, null]`，总位移 = 最后一个菱形 x。
- 验证（`111.bdg`）：菱形 x `0 → 80`（自动间隔约 0.305/拍）；播放头 `(0,0)`；
  318 个 MoveDecorations 总位移 **80.000 = 最后一个菱形 x**；装饰物 635；三张 PNG 合法。
- **修正**：播放头不需要逐拍链式移动（318 条）。改为**第一块放 1 个装饰 + 1 条
  `MoveDecorations`**（`duration = 总拍数`，`positionOffset=[最后一个菱形 x, null]`），
  与参考示例完全一致的写法；现在只有 1 条动作。
- **长度修正**：小节线/播放头的纵向长度改为 `((n−1)×laneGap + 0.4)` 格
  （首末泳道中心距 + 上下余量），不再按 `n×laneGap`（会明显偏长）。
